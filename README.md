# 剧本杀同伴数据库

AstrBot 群聊游戏插件，用于统一管理玩家的同伴、皮肤、专属物品、普通道具、星币、经验、打卡、挖矿和抽奖。插件 ID 始终为 `astrbot_plugin_juben_npc`，可直接覆盖旧版升级。

## v2.5.13 主要变化

- 保底改为玩家全局共享，不再按群号或奖池 ID 分开。玩家进入任何新群都会继续使用自己的同一份保底次数。
- 首次迁移只合并群 `1077292821` 与 `642936992` 的旧保底次数；合计超过 100 时保存为 99，其他旧群保底删除。
- 大奖按当前奖池的条目 ID 检查玩家全局库存：同伴和皮肤都缺时随机出一个，下次必出另一个；两者都有后按顺序发放当期同伴的专属物品。
- 专属物品拥有记录改为稳定栏位。后台修改同一栏位的名称后，玩家仍然拥有该栏位，并自动显示修改后的名称。
- 同伴栏的四个专属物品可在同一行显示。
- 新增购买、管理员扣除星币、管理员发放道具、玩家赠送星币、赠送权限和查询其他玩家库存。
- 新增 2、3、5 星一次性奖励，可分别配置星币和当前装备同伴的下一件专属物品。
- 第六板块只列出同伴名称，点击后严格按顺序发放下一件专属物品，不能跳着发放。

## 玩家指令

所有下列指令都可直接发送，不需要 `/` 或机器人唤醒词；旧的带 `/` 写法仍兼容。

```text
打卡
抽奖
挖矿
状态栏 [同伴或皮肤名称]
同伴栏 [页码]
道具栏 [页码]
@群友 同伴栏 [页码]
@群友 道具栏 [页码]
同伴栏 @群友 [页码]
道具栏 @群友 [页码]
切换同伴 名称
使用道具名
出售道具名 数量
购买 条目名 数量
赠送星币 @群友 数量
赠送道具名 @群友 数量
```

查询其他玩家的同伴栏或道具栏只读，不会创建新档案，也不会修改对方资产。接收赠送的玩家必须已经在数据库中出现过。

## 购买规则

第一板块可对同伴、皮肤和普通道具勾选“允许玩家购买”，并填写购买价格。

- 普通道具可一次购买多个，例如 `购买 力量药剂I 2`。
- 皮肤只能拥有一份；重复购买会失败。玩家可以先拥有皮肤，但没有所属同伴时不能切换或装备该皮肤。
- 同伴首次购买会加入同伴栏。再次购买同一同伴时，不重复建立同伴，而是按顺序发放该同伴下一件未拥有的专属物品。
- 没有可发放专属物品时，重复购买同伴会失败且不会扣星币。
- 星币不足、数量错误、名称不完整、未开放购买或价格无效时均会显示原因，且不会修改资产。

## 玩家赠送与管理员发放

管理员白名单与普通赠送权限是两套独立权限。

普通赠送权限只能把玩家自己拥有的资产转给别人：

```text
赠送星币 @群友 数量
赠送道具名 @群友 数量
```

赠送成功后会从发送者的余额或库存扣除。没有权限、余额或库存不足、赠送给自己、目标档案不存在时不会修改任何资产。

管理员白名单可以凭空发放或扣除资产：

```text
发放星币 @群友 数量
扣除星币 @群友 数量
发放道具 @群友 道具名 数量
发放同伴 @群友 同伴或皮肤名称
发放专属 @群友 同伴名称
发放权限 @群友
取消权限 @群友
```

`@群友 发放权限` 和 `@群友 取消权限` 也支持。扣除星币最低为 0，不会产生负数。发放权限只开放玩家间的“赠送星币”和“赠送道具”，不会授予管理员的凭空发放能力。

## 星级奖励

第一板块的同伴编辑区可为 2、3、5 星分别设置：

- 星币数量，填 `0` 表示不发星币。
- “发放专属物品”勾选框。

玩家经验第一次跨过对应星级门槛时立即发放一次，不依赖打开状态栏。专属物品从玩家当前装备同伴的未拥有栏位中按顺序发放；没有可发放栏位时仍标记该星级已处理，以后不会补发。升级本版本前已经达到的星级不会自动补发历史奖励。

## 抽奖与全局保底

每次抽奖消耗 10 星币并固定进行 5 抽。经验球、道具、同伴和皮肤四类概率可在第五板块配置，总和必须为 100%。

保底次数属于玩家账号本身：

- 跨群共享。
- 更换奖池 ID 不会重置。
- 新加入的群也会继续累计同一份保底。
- 达到 100 抽触发后归零。

大奖使用第一板块当前勾选的同伴 ID 和皮肤 ID：

1. 玩家缺少两者时随机发放其中一个。
2. 下次大奖发放另一个未拥有条目。
3. 两者都拥有后，显示当期同伴图片，并按顺序发放该同伴下一件专属物品。
4. 专属物品全部拥有或未配置时，按现有重复奖励规则转换为经验。

当期皮肤不要求归属于当期同伴。皮肤仍必须在总库中绑定自己的所属同伴，供同伴栏归类和装备检查使用。

## 同伴栏、皮肤与专属物品

- 同伴栏按同伴经验排序，并支持分页。
- 每名同伴的前四个专属物品在同一行显示；已拥有栏位高亮，未拥有栏位显示灰色。
- 只拥有皮肤但没有所属同伴时，同伴栏仍会显示灰色同伴和已拥有皮肤，但不能装备该皮肤。
- 专属物品按栏位编号保存。抽奖、重复购买、星级奖励、群内管理员发放和第六板块发放都调用同一套顺序逻辑。
- 修改某个栏位的名称不会清除玩家的拥有状态；同伴栏会自动显示新名称。

## WebUI 六个板块

1. 总库：维护同伴、皮肤、道具、经验球、奖池状态、购买价格、出售价格、专属物品和星级奖励。
2. 打卡模板：按皮肤、同伴、通用模板的顺序匹配背景和文字。
3. 状态栏模板：编辑文字、经验条、技能名与技能描述。
4. 挖矿模板：维护角色绑定背景和可抽取道具池。
5. 抽奖设计：维护背景、四类概率、卡片颜色和奖池 ID；奖池 ID 只用于运营标识，不影响保底。
6. 玩家资产：维护管理员白名单、普通赠送权限、玩家资产发放与扣除；专属物品只选择同伴，按钮自动发放下一件。

## 数据持久化与迁移

永久数据不保存在安装压缩包里，而是在 AstrBot 全局数据目录：

```text
<AstrBot 数据目录>/plugin_data/astrbot_plugin_juben_npc/
```

因此可发布、分享和拖入 AstrBot 安装的插件压缩包不包含玩家数据。升级插件时，只要不删除上述目录，玩家资产和后台配置都会保留。换云端时必须单独迁移这个完整目录；仅安装插件压缩包不会恢复用户数据。

主要文件：

```text
players.json             玩家星币、经验、同伴、皮肤、道具、专属物品和全局保底
characters.json          同伴、皮肤、道具、经验球及购买/星级奖励配置
gift_operators.json      管理员发放白名单
gift_permissions.json    玩家赠送权限名单
settings.json            色彩配置
checkin_templates.json   打卡模板
status_templates.json    状态栏模板
mining_templates.json    挖矿模板
draw_design.json         抽奖设计和概率
npc_assets/              同伴、皮肤、道具图片
checkin_assets/          打卡背景
status_assets/           状态栏背景
mining_assets/           挖矿背景
draw_assets/             抽奖背景
fonts/                   字体
rendered/                临时回复图片缓存，可不迁移
```

覆盖升级前仍建议备份整个 `plugin_data/astrbot_plugin_juben_npc`。迁移程序会保留旧数据备份文件，并把旧版专属物品名称记录转换为稳定栏位。

## 安装与依赖

将发布的 ZIP 直接拖入 AstrBot 插件安装页面。插件需要 Pillow，压缩包内带中文字体；AstrBot 通常会按 `requirements.txt` 自动安装依赖。

```text
Pillow>=10.0.0
```
